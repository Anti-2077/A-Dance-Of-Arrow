# A Dance Of Arrow — 화면 분리 / 기기 내 저장 버전

## 실행
- GitHub Pages 저장소의 기존 파일을 이 ZIP의 파일로 교체 업로드합니다.
- `index.html`, `pages/`, `css/`, `js/` 폴더 구조를 그대로 유지하세요.
- 로그인이나 Firebase 설정 없이 메뉴로 바로 진입합니다.

## 화면 파일
- `pages/menu.html`: 메인 메뉴
- `pages/editor.html`: 채보 에디터
- `pages/editor-play.html`: 에디터 테스트 플레이 경로 정의. 실제 플레이 무대는 아래 게임 화면과 공유합니다.
- `pages/game-play.html`: 일반 게임 플레이
- `pages/settings.html`: 키 설정 및 오프셋
- `pages/auto-chart.html`: 자동 채보 생성
- `pages/chart-library.html`: 기기 내 채보 보관함

사이트는 로그인 화면을 거치지 않고 메인 메뉴로 바로 진입합니다. 공개 채보 메뉴 카테고리는 제거했으며, 기존 기기 내 채보는 곡 선택 목록에 계속 표시됩니다. 화면은 `js/bootstrap.js`가 한 번에 불러오고, 기존 게임 런타임은 화면 상태를 전환합니다. 이 구조는 에디터에서 만든 채보/음원 참조를 페이지 이동으로 잃지 않으면서 화면별 HTML을 분리하기 위한 것입니다.


## 게임 밸런스
- 플레이 시작 시 체력은 5/20, 회복 포인트는 [0/20]입니다. 최대 체력은 20입니다.
- PERFECT는 회복 포인트 +4, GOOD은 +2, NOT BAD는 +1입니다. BAD와 MISS는 회복 포인트를 주지 않습니다.
- 회복 포인트가 20에 도달하면 체력이 1 회복되고 포인트는 0으로 돌아갑니다. 체력은 MISS에서만 1 감소합니다.
- 판정 범위는 PERFECT ±25ms, GOOD ±50ms, NOT BAD ±100ms, BAD ±150ms입니다. ±150ms를 초과한 입력은 무효이며, 노트가 150ms 늦게 지나면 MISS 처리됩니다.

## 공통 기능
- `css/common.css`: 기존 공통 디자인
- `css/menu.css`, `editor.css`, `editor-play.css`, `game-play.css`: 화면별 스타일
- `js/app-core.js`: 게임/에디터 핵심 로직
- `js/local-chart-library.js`: 로컬 채보 보관함
- `js/editor-*.js`, `js/offset-*.js`: 에디터 및 오프셋 기능
- `js/bootstrap.js`: 화면 HTML과 스크립트 로드

## 저장 방식
- 설정과 작은 데이터는 LocalStorage에 저장됩니다.
- 프로젝트 음원은 IndexedDB에 저장됩니다.
- 데이터는 현재 브라우저/기기에만 저장되며 자동 동기화되지 않습니다.
- 브라우저 데이터 삭제 시 저장 내용이 사라질 수 있으므로 중요한 채보는 JSON으로 내보내 별도 보관하세요.

Firebase Authentication 및 클라우드 동기화는 사용하지 않습니다.

## AI 자동 채보 생성 업그레이드
- `js/auto-chart-ai.js`가 음악 분석과 노트 생성을 담당합니다. `js/app-core.js` 내부 상태에 직접 접근하지 않고 `window.ADOAAutoChartBridge`를 통해서만 오프셋, 음원, 채보, 화면 전환을 주고받습니다.
- BPM은 사용자가 입력한 값을 그대로 사용합니다. AI 분석은 BPM을 자동 변경하지 않습니다.
- 브라우저 Web Audio API로 오디오를 디코딩하고 저음/중음/고음의 스펙트럼 변화와 타격 시점을 분석합니다.
- 첫 번째 강한 타격을 기준으로 잡은 뒤 곡 전체의 박자 정렬도를 함께 계산해 오프셋을 구하고, 분석 완료 즉시 공통 오프셋과 에디터 오프셋에 적용합니다. 기존 수동 오프셋은 보존해 자동 오프셋과 합산합니다.
- 최대 1/32 박자까지 분석하며, UI에서 선택한 최대 세부 박자보다 더 촘촘한 노트는 생성하지 않습니다.
- Easy / Normal / Hard / Expert 네 단계로 노트 밀도와 리듬 복잡도를 조절합니다. Easy와 Expert의 밀도 차이는 약 10배를 목표로 하되, 음악의 실제 타격음에 따라 노트 수는 달라집니다.
- 동시 입력은 전체 키 개수의 절반을 넘지 않도록 제한합니다(4키=2, 6키=3, 8키=4).
- 빠른 연타는 중앙 레인을 우선 사용하고, 반복 구간은 좌우 중앙 레인을 교차해 배치합니다.
- 생성한 채보는 기존 게임 미리보기와 에디터로 전달되며 JSON으로 내보낼 수 있습니다.
- 분석은 사용자의 브라우저 안에서 실행되며 음원은 서버로 전송되지 않습니다. 현재 엔진은 스펙트럼 기반 신호처리/규칙 기반 분석으로, 외부의 대규모 학습 AI 모델을 호출하지 않습니다.


## AI 채보 리듬 분석 강화
- 지속되는 음색/멜로디는 프레임마다 노트로 만들지 않습니다. 스펙트럼 변화가 뚜렷한 짧은 어택(타격) 중심으로 감지하며, 지속성이 높고 음색이 강하게 tonal한 구간은 억제합니다.
- 짧은 타격 사이의 최소 간격을 약 40ms로 줄여 작은 드르륵/롤/연속 타격을 더 세밀하게 감지합니다.
- 감지된 타격은 1/32 그리드에 정렬합니다. 같은 그리드 시점에 모인 타격은 하나의 이벤트로 합쳐 중복 노트가 생기지 않도록 합니다.
- 타격 강도가 클수록 동시 입력 수를 늘립니다. 최대 동시 입력은 기존 규칙대로 전체 키 수의 절반(4키=2, 6키=3, 8키=4)입니다.
- 전체 이벤트의 약 70%를 한쪽 레인 절반에 집중시키고 나머지는 반대쪽에도 배치해 단조로움을 줄입니다. 연타는 선택된 쪽의 중앙에 가까운 레인을 우선 순환합니다.
- 레인 배치 방향은 곡 파일명과 BPM에 기반해 결정적으로 선택되므로 같은 곡을 다시 생성하면 같은 방향 편향을 유지합니다.
- 분석은 스펙트럼 기반 신호처리입니다. 모든 악기/녹음 환경에서 멜로디와 타격음을 완벽히 구분할 수는 없으므로, 생성 후 에디터에서 최종 확인할 수 있습니다.


### 에디터 분할 설정
- 그리드 분할은 1/4, 1/8, 1/16, 1/32, 1/64를 지원합니다.
- 1/64 선택 시 노트 배치와 스냅 간격이 BPM 기준 64분음표 간격으로 적용됩니다.

## 에디터 반응 속도 개선
- 채보를 선택할 때 전체 노트 목록을 다시 생성하지 않고, 선택 표시와 세부 정보만 갱신합니다.
- 노트 DOM을 ID 기준으로 재사용하여 삭제/이동/실행 취소 후에도 변경된 노트 중심으로 업데이트합니다.
- 선택/삭제/실행 취소 직후 불필요하게 박자 가이드 전체를 재생성하던 중복 이벤트 처리를 제거했습니다.
- BPM 등 입력 중에는 매 글자마다 가이드라인을 다시 만들지 않고, 입력 확정 시 갱신합니다.
- 실행 취소/다시 실행 기록은 JSON 문자열 변환을 피하고 복사본 객체를 저장하며, 기록 개수는 기존과 동일하게 최근 50회로 제한합니다.
- 1/64 분할 설정과 기존 프로젝트 저장 형식은 유지합니다.


## 에디터 대량 채보 최적화
- 화면에 보이는 구간과 위아래 여유 구간의 노트만 DOM으로 표시하는 가상 렌더링을 적용했습니다. 화면 밖 노트는 채보 데이터와 저장 파일에 그대로 유지됩니다.
- 타임라인 위에서 마우스 휠을 움직이거나 오른쪽 세로 스크롤 바로 다른 시간 구간을 탐색할 수 있습니다. 기존 재생 위치 슬라이더와 연동됩니다.
- 단일 노트 삭제는 전체 채보 복사 대신 삭제한 노트와 원래 인덱스만 실행 취소 기록에 보관해 메모리 복사량을 줄였습니다. 실행 취소/다시 실행도 해당 기록을 복원합니다.
- 1/64 분할과 기존 에디터 데이터 형식은 유지됩니다.

## 2026-11-08 입력/오프셋 시스템 정리
- 채보 삭제 단축키는 스페이스바입니다. 에디터 화면에서만 선택 노트를 삭제하며, 일반 플레이 및 에디터 미리보기에서는 삭제 동작을 하지 않습니다.
- 스페이스바는 4/6/8키 키 매핑에 등록할 수 없습니다. 기존 저장 키 설정에 스페이스가 들어 있으면 해당 레인의 기본 키로 자동 교체합니다.
- 에디터 키뷰어는 에디터 전용 입력 상태를 사용합니다. 게임 플레이의 키뷰어/눌림 상태와 서로 값을 공유하지 않습니다.
- 에디터 미리보기에서는 일반 플레이 화면의 '메인으로' 버튼을 숨기고 '에디터로 돌아가기'만 표시합니다.
- 오프셋은 음원과 시간선의 시작점을 모두 0초로 유지합니다. 양수 오프셋 동안 채보 시계만 0초에 고정되고, 지정한 대기 시간이 지난 뒤 채보 이동과 판정이 시작됩니다. 시간선/재생 시계/탐색바는 음원 재생 시간 기준입니다.
- 에디터 미리보기는 재생 중인 음원의 현재 재생 시간을 기준으로 채보 이동과 판정을 계산하며, 음원이 없을 때만 내부 시계를 사용합니다.
- 중복된 오프셋 저장 스크립트를 제거하고 기존 v10 전용 저장값 및 이전 설정값을 새 설정 로더에서 순서대로 마이그레이션합니다.
- 정적 JavaScript 문법 검사와 로더의 페이지/스크립트 경로 검사를 수행했습니다. 브라우저에서 실제 음원/키 입력 플레이 테스트는 별도로 필요합니다.


## 프로젝트 JSON 내보내기

에디터 상단의 `프로젝트 JSON 내보내기` 버튼은 현재 채보와 BPM/레인/오프셋 설정, 판정선 이벤트, 화면 이펙트, 이미지 리소스, 음원 파일을 하나의 JSON 파일로 묶어 내보냅니다. 음원과 이미지는 Base64 데이터로 JSON 안에 포함되므로 음원이 큰 프로젝트는 JSON 파일도 커질 수 있습니다. 저장된 프로젝트를 열어 내보내는 경우에도 IndexedDB에 보관된 음원을 가져와 포함합니다.


## 프로젝트 JSON 내보내기 수정 (2026-11-11)
- `offset-visual-events.js`가 `saveChart.onclick`을 덮어써서 전체 프로젝트 내보내기를 채보 전용 내보내기로 교체하던 충돌을 제거했습니다.
- 내보내기 버튼은 `app-core.js`에서 단일 이벤트 리스너로 처리하며, 실행 중 중복 클릭을 막고 완료 후 버튼 상태를 복구합니다.
- 음원은 현재 선택된 Blob 또는 프로젝트 IndexedDB 저장본에서 읽고, 이펙트·채보·이벤트·이미지를 포함해 JSON으로 만듭니다.
- 이미지 파일을 읽지 못하면 조용히 누락하지 않고 오류를 표시합니다.
- 캐시 버전을 `20261111b`로 올렸습니다.


## JSON 프로젝트 내보내기 (2026-11-11)
- 지원 브라우저에서는 `프로젝트 JSON 내보내기` 클릭 즉시 저장 위치/파일명을 선택하는 시스템 저장 창을 엽니다.
- 저장 창에서 위치와 파일명을 선택하면 음원, 채보, 이펙트, 이벤트, 이미지가 포함된 JSON 프로젝트를 저장합니다.
- File System Access API를 지원하지 않는 브라우저에서는 기존 다운로드 방식으로 자동 대체됩니다.
- 저장 창을 취소하면 내보내기를 취소하며 파일을 생성하지 않습니다.

## 일반 게임 플레이 및 기본 수록곡
- 메인 메뉴의 `게임 플레이`를 누르면 별도의 곡 선택 화면이 열립니다.
- 곡을 선택하면 일반 플레이 화면으로 이동하며, 일반 플레이 화면에는 재생 탐색 바가 표시되지 않습니다.
- 일반 플레이 화면에는 에디터 복귀 버튼이 표시되지 않습니다. `곡 선택` 버튼으로 곡 선택 화면에 돌아갈 수 있습니다.
- `songs/DiDice - Phantigma.json`은 사용자가 제공한 프로젝트 JSON이며 기본 곡 목록의 첫 번째 항목으로 자동 등록됩니다.
- JSON에 포함된 Base64 음원도 브라우저에서 Blob으로 복원하여 재생합니다.

### 채보 속도 JSON 저장/불러오기
- 프로젝트 JSON에는 전체 낙하 속도를 `speed` 및 `settings.gameSpeed`로 저장합니다.
- 각 노트의 개별 `speed` 값도 함께 저장하며, 플레이 시 개별 값이 있으면 우선 적용합니다.
- JSON을 다시 불러오면 에디터 속도 슬라이더도 저장된 값으로 복원됩니다.
- 속도 정보가 없는 이전 JSON은 기본 1.0배속으로 재생됩니다.
